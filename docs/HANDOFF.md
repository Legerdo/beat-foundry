## 프로젝트 개요

**BEAT FOUNDRY**는 리듬과 인크리멘탈 시스템이 하나로 통합된 웹 게임이다.  
작업공간: `c:\Users\K\DevSpaceWorkspaces\BEAT FOUNDRY`

기술 스택: Vite + TypeScript + Canvas 2D + Web Audio API  
외부 런타임 의존성 없음 (모든 소리는 WebAudio로 합성, 외부 에셋 없음)

### 현재 버전: 1.2.0 + 후속 버그 수정 — 빌드·테스트 정상

```
npm run build   → dist/ 생성 (빌드 통과)
npm test        → Tests 42 passed (6 test files)
```

## 개발 방식 (지금까지 따라온 규칙)

1. **새 작업 전 반드시 파일을 읽어라.** 추측으로 코드를 쓰지 않는다.
2. **가격/굽기 목표를 바꾸면 `npm run sim`으로 능동·느긋한 플레이를 모두 검증한다.** 총 완료 시간만으로 노가다가 해결됐다고 판단하지 않는다. `longestGap`(구매 사이 대기)과 `castWait`(마지막 구매 후 굽기 자금 대기)를 함께 기록하고, 능동 구매 대기 60초/느긋한 구매 대기 90초/양쪽 마지막 자금 대기 60초 미만을 검사한다. 완료 상한은 능동 T1 10분/T2 7분/T3 6분, 느긋한 T1 15분/T2 11분/T3 10분이다. 실제 `economy` 플레이테스트에서 표시 가격과 차감액도 확인한다.
3. **렌더 코드 수정 후 `scripts/perf.mjs`로 4× 스로틀 측정.** 드롭 중 p95 < 8ms 유지.
4. **텍스트 추가는 반드시 `src/i18n.ts`에 양쪽 언어 모두.** `npm test`로 플레이스홀더 동치 확인.
5. **`npm run build`를 마지막에 항상 실행.** TypeScript strict 오류가 없어야 한다.
6. **플레이테스트는 `node scripts/playtest.mjs http://localhost:5391/?dev [시나리오]`.** `all`로 전체 흐름 확인.

### 직전 변경: 전체 업그레이드 비용 인하와 디버그 치트 메뉴

> 아래 할인 배율/가격/시간은 당시 기록이다. 현재 수치는 위 최신 항목을 따른다.

- 사용자가 "난이도 변경이 아니라 업그레이드 비용이 높다는 의미"라고 정정했다. 판정 창/BPM/수익/가격 성장률/굽기 목표는 변경하지 않았다. `economy.ts`의 `UPGRADE_COST_SCALE = 0.7`을 음표/모드/영구 업그레이드의 공통 기준으로 사용한다. 스파크 비용은 올림, 골드는 정수 반올림·최소 1이다. OPUS `costScale`은 22→18로 낮춰 직전 비용 대비 약 43% 낮다. 합창 첫 음표 15.12B, 다음 39.312B. 화면 가격·실제 구매·자동 단조·목표·모드·영구 업그레이드는 기존 가격 함수들을 공유한다.

### 직전 변경: 중앙 판정/획득량 팝업과 합창 가격 조정

> 아래 가격/시간은 당시 기록이다. 현재 비용은 위 전체 인하 항목을 따른다.

- 사용자 최종 요청에 따라 퍼펙트/굿/미스는 중앙 배율 바로 아래 작은 DOM 팝업으로 표시한다. 판정 12px + 실제 획득량 10px, 높이 32px이며 최신 결과만 1.4초간 보여준다. `Game.heardTime`으로 읽기 시간·fade/pop을 제어해 모든 정지 사유에서 효과가 함께 멈춘다. 모션 줄이기는 이동을 제거한다. `pointer-events:none`으로 팝업 위 클릭도 타격으로 전달된다. 트랙 전환 시 초기화한다.

### 후속 수정: 포커스 상실 자동 정지

- `main.ts`의 window blur/focus와 초기 `document.hasFocus()`를 연결했다. `Game`의 포커스 정지 사유는 설정/페이지 숨김 정지와 별개이며, 모든 사유가 해제돼야 음악·스케줄러·진행·입력이 재개된다. `Hud.syncPause()`가 정지 사유에 맞춰 기존 UI 애니메이션도 고정/재개한다.
- 화면이 보이는 상태에서 포커스만 잃으면 수익/박자/효과가 그대로 정지한다. 기존 숨김 탭/게임 종료 중 오프라인 수익 계약은 유지한다.
